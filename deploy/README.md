# Dev Thriller — Deployment

Two supported targets, both driven from the same Dockerfiles.

## Option A: VPS with Docker Compose

Cheap, simple, single-host. Good for up to a few thousand concurrent users.

1. SSH into your VPS. Install Docker + the compose plugin.
2. Clone this repo; copy `apps/backend/.env` to `./.env.prod` and fill all required fields:
   - `MONGO_URI` — Atlas SRV URI (rotate the password first)
   - `JWT_ACCESS_SECRET` + `JWT_REFRESH_SECRET` — `openssl rand -hex 64`
   - `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`
   - `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `SMTP_PORT`, `SMTP_FROM`
   - `FRONTEND_ORIGIN` — the public URL (`https://app.example.com`)
3. Boot the stack:
   ```
   docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
   ```
4. Put TLS in front. Two easy options:
   - **Caddy** — drop `deploy/Caddyfile` next to the compose file and add a `caddy:` service pointing at it. Caddy handles Let's Encrypt automatically.
   - **Cloudflare Tunnel** — `cloudflared tunnel --url http://localhost:80` and bind it to your DNS record.
5. First-boot housekeeping (run once per new cluster):
   ```
   docker compose -f docker-compose.prod.yml exec backend bun run /app/apps/backend/src/scripts/apply-search-indexes.ts
   ```
6. Put the three workers on cron (host crontab):
   ```
   0 3 * * * cd /opt/dev-thriller && docker compose -f docker-compose.prod.yml run --rm backend bun run /app/apps/workers/src/retention.ts --apply
   0 4 * * * cd /opt/dev-thriller && docker compose -f docker-compose.prod.yml run --rm backend bun run /app/apps/workers/src/audit-verify.ts
   15 5 * * * cd /opt/dev-thriller && docker compose -f docker-compose.prod.yml run --rm backend bun run /app/apps/workers/src/media-extract.ts
   ```

## Option B: Kubernetes

For horizontal scaling, multi-AZ, and rolling deploys.

Manifests live in `deploy/k8s/`:

- `namespace.yaml` — the `dev-thriller` namespace.
- `secrets.example.yaml` — template; **do not commit the real one**. Populate by:
  ```
  kubectl -n dev-thriller create secret generic dt-secrets --from-env-file=apps/backend/.env
  ```
- `dragonfly.yaml` — single-replica StatefulSet with 5Gi PVC. Swap for DragonflyDB Cloud if you prefer managed.
- `backend.yaml` — Deployment + Service + HPA (2–10 pods, 70% CPU target). Readiness uses `/ready`, liveness uses `/health`.
- `frontend.yaml` — Deployment + Service + Ingress (TLS via cert-manager). The nginx config inside the image handles `/v1` + WebSocket proxying.
- `workers-cron.yaml` — three CronJobs (retention, audit-verify, media-extract) reusing the backend image.

Deploy:

```bash
docker build -t ghcr.io/YOUR_ORG/dt-backend:latest -f apps/backend/Dockerfile .
docker build -t ghcr.io/YOUR_ORG/dt-frontend:latest -f apps/frontend/Dockerfile .
docker push ghcr.io/YOUR_ORG/dt-backend:latest
docker push ghcr.io/YOUR_ORG/dt-frontend:latest

kubectl apply -f deploy/k8s/namespace.yaml
kubectl -n dev-thriller create secret generic dt-secrets --from-env-file=apps/backend/.env
kubectl apply -f deploy/k8s/dragonfly.yaml
kubectl apply -f deploy/k8s/backend.yaml
kubectl apply -f deploy/k8s/frontend.yaml
kubectl apply -f deploy/k8s/workers-cron.yaml
```

Then point your DNS at the Ingress controller's LoadBalancer IP. cert-manager provisions the TLS cert automatically on first request.

Run the Atlas Search bootstrap once:

```bash
kubectl -n dev-thriller run atlas-idx --rm -i --restart=Never \
  --image=ghcr.io/YOUR_ORG/dt-backend:latest \
  --env="MONGO_URI=$MONGO_URI" --env="MONGO_DB=devthriller" \
  --command -- bun run /app/apps/backend/src/scripts/apply-search-indexes.ts
```

## Production environment checklist

The backend **refuses to start in production** if any of these are still at default / missing:

- `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` (must not contain `please_rotate`)
- `MONGO_URI` (must not be `mongodb://localhost`)
- `R2_*` (all three required)

This is enforced in `apps/backend/src/config/env.ts`.

## Observability

- `GET /health` — liveness. Always 200 if the process is running.
- `GET /ready` — readiness. 200 only when Mongo + Dragonfly both respond. Returns a JSON body with per-dependency status + uptime.
- `GET /docs` — Swagger UI, autogenerated from Elysia `t` schemas.
- All responses include an `X-Request-Id` header (incoming one honored when well-formed, otherwise generated). Logs include the same id via Pino child logger.

## Operations

### Mongo Atlas (primary store)

**On-demand snapshot** (UI):
1. Atlas console → Cluster → **Backup** → **Take Snapshot Now**.
2. Tag with reason (`pre-migration-2026-04-25`). Default retention is 7 days for hourly, 30 for daily.

**On-demand snapshot** (CLI):
```sh
atlas backups snapshots create --clusterName dt-prod --description "pre-migration"
```

**Point-in-time restore**:
1. Atlas console → **Backup** → **Restore Snapshot** → **Point in Time**.
2. Pick UTC timestamp. Restore to a NEW cluster (`dt-prod-restore-YYYYMMDD`) — never overwrite.
3. Validate: connect with `mongosh`, run `db.activityLog.findOne({}, { sort: { createdAt: -1 } })` and confirm timestamp.
4. Update `MONGO_URI` in the `dt-backend-secrets` Secret. Rolling restart (see below).
5. Once cut over, retire the old cluster after a 24h soak.

**No Atlas? `mongodump` flow**:
```sh
# Backup (run from a jump host with network access)
mongodump --uri "$MONGO_URI" --gzip --archive=dt-$(date +%F).gz
# Restore
mongorestore --uri "$NEW_URI" --gzip --archive=dt-2026-04-25.gz --drop
```
Schedule via the same CronJob runner as retention; ship the archive to R2 with `aws s3 cp ... s3://dt-backups/...` (R2 is S3-compatible).

### Cloudflare R2 (file blobs)

**Enable versioning + lifecycle** so soft-deleted files are recoverable for the workspace's `retention.fileDays` window before the bucket auto-deletes them.

Wrangler config (`wrangler.toml` snippet for the R2 bucket):
```toml
[[r2_buckets]]
binding = "DT_FILES"
bucket_name = "dev-thriller"
# Versioning toggled in the R2 dashboard (UI only as of writing).
```

Lifecycle rule (R2 dashboard → bucket → **Object lifecycle rules**):
```json
{
  "rules": [
    {
      "id": "expire-soft-deleted",
      "status": "Enabled",
      "filter": { "prefix": "" },
      "noncurrentVersionExpiration": { "noncurrentDays": 365 },
      "abortIncompleteMultipartUpload": { "daysAfterInitiation": 7 }
    }
  ]
}
```

Terraform alternative:
```hcl
resource "cloudflare_r2_bucket_lifecycle_configuration" "files" {
  account_id = var.cf_account_id
  bucket     = "dev-thriller"
  rule {
    id     = "expire-soft-deleted"
    status = "Enabled"
    noncurrent_version_expiration { noncurrent_days = 365 }
    abort_incomplete_multipart_upload { days_after_initiation = 7 }
  }
}
```

**Restore a file**: R2 dashboard → object → **Versions** → restore. For bulk
restore (workspace migration) use rclone: `rclone copy r2:dev-thriller-archive r2:dev-thriller --include "ws_<id>/**"`.

### DragonflyDB (cache + pubsub)

Dragonfly is a cache. Losing it is recoverable on the next request — ACL
entries rebuild lazily, sessions re-validate JWTs, presence repopulates. The
PVC-backed StatefulSet (`deploy/k8s/dragonfly.yaml`) survives pod restarts; a
total volume loss is non-fatal.

**Force ACL cache flush** (after a permission model change):
```sh
kubectl exec -n dev-thriller dt-dragonfly-0 -- redis-cli --scan --pattern 'acl:*' | \
  xargs -n 100 kubectl exec -n dev-thriller dt-dragonfly-0 -- redis-cli DEL
# Or nuke the whole DB (fast, safe in dev):
kubectl exec -n dev-thriller dt-dragonfly-0 -- redis-cli FLUSHDB
```

### Secrets rotation

| Secret                | Rotation                                                                       |
| --------------------- | ------------------------------------------------------------------------------ |
| `JWT_ACCESS_SECRET`   | **Hard cut** — invalidates all access tokens. Refresh tokens still valid.      |
| `JWT_REFRESH_SECRET`  | **Hard cut** — forces re-login for every user. Schedule a maintenance window.  |
| `R2_*`                | Update Secret → `kubectl rollout restart deployment/dt-backend`.               |
| `RESEND_API_KEY`      | Update Secret → rollout restart. No traffic impact.                            |
| `MONGO_URI`           | Atlas: rotate password → update Secret → rollout restart.                      |

**Graceful JWT rotation (recommended):** add `JWT_ACCESS_SECRETS_PREVIOUS=<old>`
to the env, deploy with both old and new secrets accepted on verify, wait
> `JWT_ACCESS_TTL_MIN`, then drop the previous secret. **Not implemented in v1
> backend** — requires `accessJwt.verify` to try multiple secrets. Tracked
> separately; for now treat access-secret rotation as a hard cut.

### Cycling pods

```sh
# Rolling restart — zero downtime if replicas >= 2.
kubectl rollout restart deployment/dt-backend -n dev-thriller
kubectl rollout status  deployment/dt-backend -n dev-thriller

# Workers (CronJobs reschedule on next tick — no manual restart needed).
kubectl get cronjobs -n dev-thriller
```

### Draining the thumb queue

```sh
# Inspect.
kubectl exec -n dev-thriller dt-dragonfly-0 -- redis-cli LLEN thumb:jobs

# Peek at the next 10 jobs.
kubectl exec -n dev-thriller dt-dragonfly-0 -- redis-cli LRANGE thumb:jobs 0 9

# Force a drain (re-enqueue stuck jobs from a parking list).
kubectl exec -n dev-thriller dt-dragonfly-0 -- redis-cli RENAME thumb:dead thumb:jobs

# Nuke (last resort — orphans thumbnails until media-extract re-walks).
kubectl exec -n dev-thriller dt-dragonfly-0 -- redis-cli DEL thumb:jobs
```

### Common alerts

| Alert                                | First check                                                                  |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| `/ready` returning 503               | Mongo or Dragonfly connection. `kubectl logs deploy/dt-backend --tail 100`.  |
| `thumb:jobs` depth > 1000            | Worker stalled. `kubectl logs job/dt-media-extract`. Drain queue if needed.  |
| `audit-verify` cron failing          | Chain broken — read `brokenAt` from logs. **Page on-call.** Do not auto-fix. |
| p95 latency > 1s on `/v1/messages`   | Mongo slow query — check Atlas Performance Advisor. Index missing?           |
| 5xx rate > 1%                        | Pull recent errors from `/v1/admin/metrics` then deep-dive logs by `requestId`. |

### Cron schedules

```yaml
# deploy/k8s/cronjobs.yaml (excerpt)
retention:     "0 3 * * *"   # daily 03:00 UTC
audit-verify:  "0 */6 * * *" # every 6h
media-extract: continuous (Deployment, polls thumb:jobs)
```

`retention` runs in dry-run by default; flip to `--apply` once the dry-run output looks sane (audit cuts especially — once gone, gone).
